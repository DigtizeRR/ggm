# Workshop Shortcode Shared Left-Aligned Headings Plan

## Implementation status

Approved and implemented on 2026-09-12. All six shortcode-generated section H2 elements now use only `ggm-ws-section-heading`. The shared desktop and mobile rules are left-aligned, legacy heading selectors have no remaining production references, PHP syntax and whitespace checks pass, and the pre-existing mentor CSS customization remains preserved.

## Requested outcome

Use one HTML class and one shared style system for every main section heading rendered by the workshop content shortcodes. All of those headings must be left-aligned on desktop and mobile.

The shared class will remain:

`ggm-ws-section-heading`

## Scope definition

The audit identifies these six front-end workshop content shortcodes as section components with their own main H2:

| Shortcode | Current main-heading class | Required result |
| --- | --- | --- |
| `[ggm_workshop_discover]` | `ggm-ws-block__heading ggm-ws-discover__section-heading` | `ggm-ws-section-heading` |
| `[ggm_workshop_why_different]` | `ggm-ws-section-heading` | Keep shared class |
| `[ggm_workshop_why_workshop_is_different]` | `ggm-ws-section-heading` | Keep shared class and left-align the screenshot heading |
| `[ggm_workshop_journey]` | `ggm-ws-section-heading` | Keep shared class |
| `[ggm_workshop_perfect_for]` | `ggm-ws-block__heading ggm-ws-perfect-for__section-heading` | `ggm-ws-section-heading` |
| `[ggm_workshop_faq]` | `ggm-ws-section-heading` | Keep shared class |

This deliberately excludes card/item titles, mentor names, FAQ questions, form titles, status messages, the booking-card rich-text hero, and `[ggm_workshop_heading]`. Those are not section H2 elements generated by this family of content-section shortcodes and have different semantic/layout responsibilities.

The standalone Workshop template also contains `.ggm-ws-section-title` headings, but those are template markup rather than headings emitted by the shortcodes above. They will remain unchanged unless template headings are requested separately.

## Audit findings

### 1. The PHP output is only partially standardized

`public/class-ggm-shortcodes.php` currently emits six section-level H2 elements:

- Why Different, Why This Workshop Is Different, Journey, and FAQ already emit only `ggm-ws-section-heading`.
- Discover and Perfect For still emit the older `ggm-ws-block__heading` plus a section-specific class.

Therefore, administrators cannot target every shortcode section heading through one dependable class today.

### 2. Two separate desktop heading systems conflict with the request

`assets/css/ggm-public.css` currently has:

- `.ggm-ws-block .ggm-ws-block__heading`, using `32px`, weight `600`, centered text, and `1em` bottom spacing.
- `.ggm-ws-section-heading`, using Space Grotesk, `32px/38px`, weight `600`, centered text, and `28px` bottom spacing.

Even where the visual size is similar, the two selectors do not establish one source of truth for font family, line height, margin, or alignment.

### 3. Mobile contains a direct forced-center override

Inside `@media (max-width: 767px)`, `.ggm-ws-discover__section-heading` is explicitly included in a group with `text-align: center !important`. This would continue centering the Discover H2 even if the general shared class were changed to left alignment.

The final mobile typography block also targets both `.ggm-ws-block .ggm-ws-block__heading` and `.ggm-ws-section-heading`, which preserves the duplicate styling paths.

### 4. Section content alignment must remain independent

Discover cards and their item text are intentionally centered, while the requested main heading must be left-aligned. The fix must remove only the main-heading selector from the forced-center group. It must not change card titles, descriptions, images, grids, or their mobile 2-column behavior.

### 5. Existing unrelated working-tree change

`assets/css/ggm-public.css` already contains an uncommitted administrator/user change to the mentor section’s maximum width, colour, and font inheritance. The implementation will preserve that change exactly and edit only the audited heading selectors.

## Proposed implementation

### Phase A: normalize shortcode markup

In `public/class-ggm-shortcodes.php`:

1. Change the Discover main H2 to use only `class="ggm-ws-section-heading"`.
2. Change the Perfect For main H2 to use only `class="ggm-ws-section-heading"`.
3. Leave the other four H2 elements on that same class.
4. Preserve the H2 element, heading text source, escaping, conditional `show_heading` behavior, and stored heading overrides.

After this change, all six main section headings will have exactly the same class attribute.

### Phase B: consolidate desktop CSS

In `assets/css/ggm-public.css`:

1. Make `.ggm-ws-section-heading` the only shared workshop section-heading rule.
2. Retain the established desktop typography:
   - Space Grotesk;
   - normal style;
   - weight `600`;
   - `32px` font size;
   - `38px` line height;
   - `28px` bottom margin.
3. Change the shared alignment to `text-align: left` and give it sufficient authority against theme/Elementor heading alignment.
4. Remove the obsolete `.ggm-ws-block .ggm-ws-block__heading` heading rule after its two PHP consumers are migrated.

### Phase C: consolidate mobile CSS

Within the existing `max-width: 767px` rules:

1. Keep only `.ggm-ws-section-heading` as the selector for these six main headings.
2. Retain the approved mobile typography of Space Grotesk, normal style, weight `600`, `25px` size, and `28px` line height.
3. Explicitly keep `text-align: left` at mobile width.
4. Remove `.ggm-ws-discover__section-heading` from the forced-center selector group.
5. Remove `.ggm-ws-block .ggm-ws-block__heading` from the mobile typography group because no section heading will use it.
6. Leave Discover item headings/descriptions centered and leave all section grids/layouts unchanged.

### Phase D: remove obsolete main-heading hooks only

After verifying no remaining consumers, remove the two obsolete main-heading-only class names from shortcode markup/CSS usage:

- `ggm-ws-discover__section-heading`
- `ggm-ws-perfect-for__section-heading`

Section wrapper classes and item-level classes remain untouched.

## Files expected to change after approval

- `public/class-ggm-shortcodes.php` — normalize Discover and Perfect For H2 class attributes.
- `assets/css/ggm-public.css` — one desktop rule and one responsive override for the shared heading class; remove conflicting obsolete selectors.
- `ggm-member-dashboard.php` — patch-version bump for deployment/cache identification.

No JavaScript, admin fields, stored metadata, Elementor Dynamic Tags, shortcode names, or section layouts require changes.

## Verification plan

### Static verification

1. Search all shortcode rendering code and confirm each of the six section H2 elements contains exactly `ggm-ws-section-heading`.
2. Confirm the obsolete `ggm-ws-block__heading`, `ggm-ws-discover__section-heading`, and `ggm-ws-perfect-for__section-heading` selectors have no remaining production references.
3. Confirm there is one base CSS rule and one responsive override for `ggm-ws-section-heading`.
4. Run `php -l` for changed PHP files and `git diff --check`.
5. Verify the pre-existing mentor CSS edit is unchanged in the resulting diff.

### Browser/viewpoint verification

Check the six shortcodes at:

- 320 x 568;
- 390 x 844;
- 430 x 932;
- 767px and 768px boundaries;
- 1024px and 1440px desktop widths.

For each viewport, verify:

1. The main section H2 is left-aligned.
2. Long headings wrap naturally from the left without clipping or horizontal overflow.
3. Desktop headings compute to `32px/38px`, weight `600`.
4. Mobile headings compute to `25px/28px`, weight `600`.
5. Every heading uses Space Grotesk when the font is available, with the existing sans-serif fallback.
6. Discover card content remains centered and its mobile 2-column grid remains unchanged.
7. Why Different cards, Why Workshop copy/image columns, Journey cards, Perfect For items, and FAQ accordions retain their current layouts.
8. `show_heading="no"` still suppresses headings where that attribute is supported.
9. No Elementor/theme global heading rule re-centers the shared class.

## Acceptance criteria

- All six shortcode-generated workshop section H2 elements use only `ggm-ws-section-heading`.
- Every one of those headings is left-aligned on desktop and mobile.
- Typography remains `32px/38px` on desktop and `25px/28px` on mobile, at weight `600`.
- There is no duplicate legacy main-heading CSS path.
- Card/item text alignment and every section layout remain unchanged.
- The user’s current uncommitted mentor CSS edit is preserved.
- Syntax, selector, whitespace, responsive, and regression checks pass.
